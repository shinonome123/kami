# Kami 本地化工作台

面向中文源文到日语、韩语、台湾繁中、法语、泰语的 AI 本地化工作台。Directus + PostgreSQL 提供语言资产后台，五套目标语言术语在存储、权限和检索层强制隔离，不以英文为中间语言。

## 已实现

- Directus 12.2.0 + PostgreSQL 资产后台、表格管理、筛选、审批和修改记录
- 日、韩、繁中、法、泰五张物理独立术语表和 API 检索入口
- 宣发、公告、道具名、道具描述、UI、规则、对白、社媒等自动语体识别
- 精确、别名、模糊匹配，以及领域/语体/批准状态加权
- `.xlsx` / `.csv` 中外文表格上传，自动识别中文列及日、韩、繁中、法、泰目标列
- 术语表拖入后立即执行 AI 结构识别；无表头、前置说明行和元数据列不再阻断上传，AI 不可用时回退整列规则推断
- 短对照自动进入术语候选，完整双语句段自动分流到当前目标语言的翻译记忆和风格证据
- 规则去噪、重复合并、现有术语检查、译法冲突提示与可选 AI 二次清洗
- 导入批次、候选判断依据、原表行号和人工采用结果完整留存在 Directus
- OpenAI-compatible 模型服务，兼容本地 Ollama/LM Studio/vLLM 或云端服务
- 按目标语言、语体和领域生成版本化风格规范，翻译任务固定记录实际使用版本
- 翻译前检索同语言、同语体相似译例；翻译后执行硬 QA + 结构化 AIQA，由后端按问题严重度计算百分制分数
- 独立 Auto QA 页面：粘贴原文与译文即可做逐句质检——先按句切分并自动对齐（语义向量优先，Embedding 不可用时由模型逐句对齐，支持拆句/并句合并，可标出整句漏译/增译），再对每一句分层独立审查：语言正确性专项（拼写/语法/标点，模型）与品牌名/格式/一致性（本地规则）计入基本检查维度、语义忠实性（着重检查项，critical 封顶 65 分）、nuance 一致性（对照风格规范、已批准译例与历史风格证据）；综合分按 20 / 50 / 30 加权，模型不可用时自动只跑本地基本检查层；每次质检自动存为任务中心里的 Auto QA 报告，可回放不重烧模型
- 批次分享验证页：翻译批次与 Auto QA 报告均可一键生成分享链接（局域网免登录访问，token 即权限），创建即时返回；分享任务进入任务中心「分享验证」类型，语素拆解与字面直译由后台任务生成（进度可见、服务重启后续跑、链接长期有效可反复查看），直译为连贯的中文成句（词块释义拼接会被拒绝重写或隐藏）；同事在独立分享页查看每段的原文、译文、QA 评分与问题，Auto QA 分享还带文档级三维评分、对齐说明与整句级漏译/增译；同事可逐段提出要求（可附建议译法），反馈进入任务中心的待采纳队列，采纳后写入风格证据池（满 8 条且通过蒸馏闸门时自动生成风格草稿），忽略则仅留档
- 右上角反馈铃铛：自动轮询（15 秒）分享页收到的同事反馈，新反馈到达时弹出提醒并显示未处理角标；点开铃铛集中展示全部待批准反馈（原文、当前译文、要求与建议译法），逐条"批准入风格"（写入风格证据池）或忽略，无需到任务中心逐个翻找
- 后台任务中心：术语导入（识别清洗与入库全程进度可见、历史批次可回看）、Embedding 重建（后台执行，探针发现外部向量服务不可用时自动改用本地词面向量）与批次导出（后台合并生成 Excel，完成后一键下载，刷新页面不丢失）统一进入任务中心"后台任务"类型，进行中显示进度、失败显示原因、可删除
- AIQA 低于 90 分自动最小修订并重新盲审，最多两轮；通过后沉淀机器验证译例，问题译文进入独立 QA 案例库
- 审校证据分权威等级：只有人工批准的译例（人工采纳、表格导入）会作为"已批准译例"提交给审校模型；本系统自己 QA 通过后写回的机器译文单独列为 machineDrafts，仅用于发现同一文档内自相矛盾，提示词明确禁止拿它当正误依据。否则一次错误会在下一次审校里升格为规范
- Auto QA 分数按段平均而非全文累加：每段独立计分后取平均，坏掉一段只影响 1/段数；阻断问题在段级压到 60/65，文档级封顶 65，另有 `blockedSegments` 计数区分"坏一段"与"全坏"
- 目标语言标点约定进入本地硬检查：中文标点混入日/韩/法/泰译文、作品名括号不符合目标语言约定都会被指出（`src/orthography.mjs` 按语种配置，同一符号重复出现只报一条），同时把约定注入翻译提示词，从源头减少照搬。当前作品名约定：日语 `『』`、韩语 `《》`、繁中 `《》`、法语 `« »`；法语另检查 `; ! ? :` 前及 `« »` 内侧的不可断行空格。韩语正字法对多种括号都允许，此处取本项目既有人工资产的统一写法，改约定只需改 `PUNCTUATION_POLICY`
- 数字按**数值等价**校验而非字面包含：中文日期简写（820 = 8 月 20 日）展开为目标语言写法不再判成漏掉受保护内容；只有数字确实无法从译文还原时提示复核。带单位的数值（50%、100元）仍要求原样保留
- 业务领域同样自动识别：语体已决定领域时直接采用（宣发→市场营销、社媒→社区运营），否则按正文关键词推断，最后回落默认；界面下拉新增「自动识别」并作为默认值。术语导入与翻译共用同一份领域规则
- **领域是收窄维度，永不让检索归零**：记忆、QA 案例按 `domain` 严格过滤，而本项目 99% 资产都归在 game 下（风格规范 7/7、记忆 592/597），选中或判成其他领域会让参考译例直接清零。现在统一先按不限领域取回、再在内存收窄，收窄后为空则退回全量并在界面标注「该领域无资产，检索已放宽到全部」
- 语体与领域的判定结果当场可见：下拉旁实时显示「语体 宣发文案（表格声明）· 领域 市场营销（语体决定）· 置信度 92%」，不必等翻译跑完；Auto QA 报告的对照证据里同样列出
- 语体分类优先读需求表自己声明的用途：`位置` / `描述` 等列命中关键词时直接采用（视频标题→宣发、导航栏文本→UI、FAQ→通用），比从正文猜测可靠；人工指定语体仍然优先，无描述时回落原有启发式
- fidelity 维度按**信息点**判定：先从原文列出可核实的信息点（事实、数字、日期、名称、平台、条件、否定、承诺强度），再逐个检查能否从译文还原；中文话语标记、程度副词、范畴词、代词显化、句子拆合与语气词改写一律不算漏译增译
- 可选 Embedding 模型（如 nomic-embed-text）启用语义向量检索：记忆、QA 案例与风格证据写入时自动向量化，检索混合词面相似度与余弦打分；未配置时自动回退词面检索
- 单句与批量译文均可人工编辑后“采纳为正式译法”：写入人工批准记忆与风格证据，同句旧机器译文自动降权
- 任务后复盘：批量翻译完成后自动复盘 QA 轨迹与人工采纳证据，跨批次累计风格证据达阈值后蒸馏新的风格规范草稿，并蒸馏全局译者画像（每目标语言一份，翻译时始终注入）
- 风格蒸馏闸门：同一作用域内只要还有待审核的风格草稿就不再生成新草稿；上一版蒸馏之后，证据池必须再新增满一个增长窗口（默认 8 条）才会重新蒸馏。复盘产出的增量补丁走同一道闸门，因此一个作用域在任何时刻最多只有一个待审草稿，界面会显示本次跳过的具体原因（阈值未到 / 有待审草稿 / 增量不足）
- 改动式风格学习：人工采纳时同时留存被替换掉的机器初稿，蒸馏时模型看到的是 `原文 / 机器初稿 / 人工定稿` 三元组——**人改了什么**才是风格信号，只看定稿无法区分改的是语气、长度还是称谓。原样采纳与表格导入的对照分别标为 confirmed / imported，权重更低
- 风格反例入池：同事在分享页只提出问题、没有给出改写时，被否决的正是当前译文，这条译文按反例（negative）入库并保留否决理由，绝不会当作正例喂给模型；译者画像与 Auto QA 的参考证据都只取正例
- 风格草稿配对评测：草稿可与当前生效版本在人工终稿留出集上做配对评测，唯一变量就是风格规范本身（技能、留出集、检索隔离两侧完全一致）。AIQA 始终以**当前生效版本**为尺子给两边打分，避免草稿用自己的标准给自己评分；因此 QA 分只作回归护栏，晋升理由只认与人工终稿的编辑距离、强制术语与硬错误。评测结论反对时激活会被拦下，确需启用必须显式忽略结论，该决定连同依据一起记录在规范上
- 风格规范与译者画像采用人工闸门：AI 蒸馏产物一律进入草稿，在术语库页对比新旧差异后激活才参与翻译
- 批量翻译进度保存在服务端（JSON 文件或 Directus batch_runs），刷新页面后自动恢复
- 译文中实际采用的正式术语以红色虚线标记，悬停可查看中外术语对照
- 近似、错字和字符重排命中只作为智能候选；译文对应表达以蓝色虚线标记，可点击确认并原位替换为正式译法
- 单句翻译与批次 / 文件翻译双模式；支持粘贴长文以及 `.txt`、`.md`、`.docx`、`.xlsx`
- 文件按结构、换行和完整句子自动分段，逐段携带相邻上下文执行翻译、术语检查和 QA
- Excel 拖入后先由 AI 识别表头行及正文、位置/备注、DDL/字数/语种约束、已有译文等列角色；无表头时根据列分布和内容样本自动推断
- Excel 只把正文列生成翻译单元，同一行的补充信息、约束和已有译文作为 Context Pack 输入，不会被误当正文翻译
- 批次可暂停续跑、跳过分段、编辑译文、重试失败项，并合并导出为原文件格式
- 收敛为翻译、Auto QA、术语导入、术语库等页面；页面主操作统一位于页头

## 运行

要求 Node.js 20 或更高版本、Docker Desktop 和 Docker Compose。首次运行：

```powershell
npm run directus:up
npm run directus:provision
npm start
```

然后打开：

- Kami 工作台：`http://127.0.0.1:4173`
- Directus 资产后台：`http://127.0.0.1:8055/admin/content/terms_ja_jp`

管理员邮箱和密码保存在本机 `directus/.env`，该文件已加入 `.gitignore`。Kami 服务端使用单独的最小权限 Service Token，不向浏览器暴露管理员令牌。

常用管理命令：

```powershell
npm run directus:up
npm run directus:down
npm run directus:provision
npm run directus:snapshot
```

`directus:provision` 是幂等的，可以安全地重新检查缺失集合、字段、权限和种子数据。Schema 快照保存在 `directus/schema/snapshot.yaml`。

**升级提示**：改动式风格学习与风格评测新增了 `style_evidence.machine_translation` / `polarity` / `note` 与 `style_profiles.evaluation` 字段。Directus 模式下需要重新执行 `npm run directus:provision`；未执行时这些字段写入会失败，历史证据按正例回落，不影响既有翻译流程。

**启动容错**：`KAMI_STORE=directus` 时如果 Directus 不可用（Docker 未启动、健康检查失败或缺少 token），Kami 不会崩溃，而是自动回退到本地 JSON 存储，并在控制台、健康检查接口和页面顶部横幅中告警。Directus 恢复后重启服务即自动回到资产后台模式。注意：回退期间的写入保存在 `data/` 下，不会自动同步回 Directus。

默认模型地址是本地 Ollama 的 OpenAI-compatible 端点：

```text
Base URL: http://localhost:11434/v1
Model: qwen3:14b
```

可以在界面右上角“模型设置”中修改。Base URL、模型名称和 API Key 会保存在本机 `data/runtime/`；Key 使用 Windows 当前用户级 DPAPI 加密，不会以明文写入项目，也无法由其他 Windows 用户或复制到其他电脑后直接解密。该目录已加入 `.gitignore`。

Embedding 服务（语义向量检索用）可独立配置：模型名称、Base URL 与 API Key 三项单独设置，留空时回退到主模型配置。主模型 API 不支持 `/embeddings` 端点时（如 DeepSeek 官方 API），可把 Embedding 指向本地 Ollama（如 `nomic-embed-text`）或其他向量服务。

“模型设置”中还可以填写输入/输出价格（美元 / 百万 token）。两者都填写后，技能评测会自动启用真实成本门禁（按每次模型调用返回的 token 用量计费）；留空则成本门禁保持跳过，不会因为未计量而锁死晋升。对应的环境变量为 `LLM_INPUT_PRICE_PER_MTOK` 与 `LLM_OUTPUT_PRICE_PER_MTOK`。

环境变量优先于本地持久化配置，也可以使用：

```powershell
$env:LLM_BASE_URL='https://your-provider.example/v1'
$env:LLM_API_KEY='your-key'
$env:LLM_MODEL='your-model'
npm start
```

DPAPI 与当前 Windows 用户身份绑定。重装系统、删除 Windows 用户或迁移到另一台电脑时，需要重新输入 Key。

## 数据隔离

正式术语分别存放在五张 PostgreSQL 表中：

```text
terms_ja_jp
terms_ko_kr
terms_zh_hant_tw
terms_fr_fr
terms_th_th

translation_memory_ja_jp
translation_memory_ko_kr
translation_memory_zh_hant_tw
translation_memory_fr_fr
translation_memory_th_th
```

每次资产查询和翻译请求必须提交受支持的 `locale`。后端通过固定白名单把 locale 映射到唯一表名，不接受客户端指定任意集合，也不存在跨语言 fallback。`data/assets/*.json` 继续作为可读的初始迁移源和离线回退数据，不是 Directus 模式下的正式写入目标。

共享后台集合包括：

- `corpus_documents`：中文原始语料和切段结果
- `term_import_batches`：表格上传、清洗和入库批次
- `term_candidates`：中外术语候选、目标语言、评分、判断依据和处理状态
- `style_profiles`：目标语言与语体规则
- `style_evidence`：从双语长句提取的分类风格证据
- `qa_runs`：每次 AIQA 的检索证据、问题、分数与修订轨迹
- `qa_cases`：低分译文、修订译文和问题类型

## 批量术语导入

进入“术语导入”，拖入 `.xlsx` 或 `.csv` 即会自动开始结构识别，不需要补表头或再次点击开始。表格可以只含一个目标语言，也可以同时含五个目标语言。系统会：

可直接复制 `samples/term-import-template.csv` 作为导入模板；不需要的目标语言列可以删除。

1. 由 AI 结合整列和成对行关系识别中文列、目标语言列、表头或无表头结构，并由后端校验真实列号。
2. 去除网址、纯数字、空值、重复对照和元数据；完整句子不再当术语，而是进入翻译记忆和风格证据。
3. 检查当前目标语言库中的已存在项及同源词译法冲突。
4. 在启用时调用模型做二次术语判断；模型不可用会自动回退本地规则。
5. 仅把人工勾选的候选写入其对应语言物理表。
6. 完整句段证据按语种、语体、领域跨批次累计；达到阈值（默认 8 条）且通过蒸馏闸门后生成新的风格规范草稿，在术语库页对比新旧差异、跑配对评测并人工激活后生效。阈值与增长窗口分别由 `KAMI_STYLE_DISTILL_THRESHOLD` 和 `KAMI_STYLE_DISTILL_GROWTH_WINDOW` 调整。

候选中文和译法可以在审核表格中修改。自动判定为“需复核”的项目默认不勾选，“已存在”和“已排除”的项目不能直接导入。

## 批次与文件翻译

进入“翻译”，切换到“批次 / 文件翻译”。可以直接粘贴长文，也可以上传 TXT、Markdown、DOCX 或 XLSX 文件。分段不使用固定字数：默认以一个完整句子作为翻译单元，也可以切换为一个自然段、Word 段落或 Excel 单元格作为翻译单元。

文件拖入后会自动解析，不需要手动添加或指定表头。对于 Excel，系统先发送列统计、部分行样本和规则建议给当前模型，识别正文、补充信息、约束、已有译文和忽略列；模型结论会经过后端列号和角色白名单校验。模型暂时不可用时自动回退到本地结构规则，并在界面明确标注“规则降级识别”。

系统先展示完整分段队列，不会直接开始翻译。启动批次时先对整份文档确定统一语体与基础风格，再为每个翻译单元携带上文、下文、文档位置、当前行的位置/备注、DDL/长度/语种约束、已有参考译文、当前目标语言术语匹配和风格配置。上下文只用于消歧与保持连贯，提示词明确禁止把补充信息或相邻内容混入当前译文。当前段完成后可以暂停，已完成进度会留在浏览器页面中。每段都会显示 QA 状态，失败项可以继续重试。导出时，未勾选或未完成的部分保留原文；DOCX 写回原段落，XLSX 只写回识别出的中文正文单元格，TXT 与 Markdown 保留原换行结构。

## 持续学习与翻译技能

“学习中心”把每次翻译看成一条可追溯轨迹，而不是直接让模型改写自己的生产提示词。学习范围由 `目标语言 × 内容语体 × 业务领域 × 项目` 四个维度严格隔离，日、韩、繁中、法、泰之间不会共享技能版本。

- `learning_trajectories` 保存原文、初译、终译、使用过的术语/记忆/风格资产、AIQA 前后指标、人工决定、模型与提示词版本。
- `translation_skills` 保存版本化翻译策略。生产只读取当前 `champion`；模型复盘轨迹后生成的改进始终先成为 `challenger`。
- `skill_evaluations` 保存 Champion 与 Challenger 在独立人工终稿留出集上的逐项对比和晋升决定。

候选技能只能调整上下文范围、检索数量、风格指令与 QA 门槛等策略，不把某个偶然译法硬编码成通用规则。候选使用过的所有轨迹都会从留出集排除；至少积累 20 条独立、人工批准的终稿后，系统才会真正重跑新旧版本。强制术语正确率或硬错误发生退化时一票否决，QA、相对人工终稿的编辑距离、延迟等指标也必须满足门槛。只有评测结论允许晋升时，界面才开放人工批准；批准和回滚都保留完整版本链。学习存储暂时不可用时只会暂停沉淀，不会阻断正常翻译。

评测以**后台任务**运行：同一时刻只跑一个评测，界面实时显示逐对进度；每完成一对就落盘检查点（`data/learning/jobs/`），服务重启后任务标记为中断，可续跑剩余样本而不是从头重烧模型调用。评测前会剔除与留出原文同源的翻译记忆、QA 案例与风格/画像正反例，防止标准答案泄漏进评测上下文。

候选生成支持**自动提议**：同一作用域内人工批准的终稿达到阈值（默认 10 条，可用 `KAMI_AUTO_PROPOSE_THRESHOLD` / `KAMI_AUTO_PROPOSE_GROWTH_WINDOW` 调整）且当前没有待评测候选时，系统会在后台自动生成 challenger；评测与激活仍必须人工执行。自动提议的记账信息保存在 Champion 技能的 `metadata` 字段（Directus 模式下需运行 `npm run directus:provision` 创建该字段）。

风格规范走的是**另一条**评测线：`translation_skills` 评的是检索条数、附加指令与 QA 门槛等策略，`style_profiles` 评的是风格文本本身。在术语库页的风格草稿卡片上点“评测”，系统会用当前 champion 技能把草稿与当前生效版本跑同一组人工终稿留出集（至少 12 条，已剔除蒸馏时用过的原文及其去标点同形变体），只让风格规范这一个变量变化。

评测有两条不可省的规矩：AIQA 会读风格规范当作 nuance 尺子，所以两侧一律用**当前生效版本**打分，否则草稿等于自己给自己判卷；相应地，QA 分与合成接受率只保留“不得下降”的护栏作用，能作为晋升理由的只有与人工终稿的编辑距离、强制术语正确率和硬错误数——这三项不受风格规范影响。评测结论写在草稿的 `evaluation` 字段上；结论反对时激活返回 409，确需启用要显式忽略结论，届时 `activationBasis` 会记为 `forced`，未评测直接启用记为 `unevaluated`。

模型返回的策略补丁是不可信输入：入库前经过白名单校验与净化——未知区块和字段丢弃、数值按区间夹紧、规则与指令长度截断、控制字符剥离，并拦截"忽略以上规则"类中英文注入特征；净化明细记录在候选的 `metadata.sanitization` 并在学习中心展示。

## 当前原型边界

- 旧版 `.xls` 需先另存为 `.xlsx`；JSON、YAML、PO、XLIFF 和游戏资源包尚未接入结构化回写。
- DOCX 会保留文档容器、段落和非文本对象，但一个段落内部跨多个样式 Run 的文字在写回时会合并到首个 Run；复杂排版文档仍建议导出后人工检查。
- 模型不可用时仍会使用本地整列规则推断；纯汉字日文、极短样本及高度相似的简繁列仅靠规则存在歧义，此时可在导入策略中指定目标语言后重试。
- 当前 AI 只负责候选保留/排除判断，不会擅自改写原表中的中外术语。
- 智能术语当前结合编辑距离、字符重排、别名和模型译文对齐；完全没有词面关联的同义概念仍建议补充别名，后续可增加多语言向量召回。
- 模型质量取决于接入的模型和为各语言积累的正式资产。
