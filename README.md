# Kami 本地化工作台

中文源文到日语、韩语、台湾繁体中文、泰语的 AI 本地化工作台，专做东方语言，不以英文作中间语言。

它和"接一个模型来翻译"的区别在于：每一次人工判断都会落成可检索的资产，而这些资产受治理约束——有有效期、有适用范围、有审批状态。机器自己产出的东西永远进不了正式资产，只有人工采纳才能。系统靠这条边界保证"越用越准"不是自我循环。

- 后台：Directus 12.2.0 + PostgreSQL，四套目标语言术语在存储、权限和检索层物理隔离
- 模型：任意 OpenAI-compatible 服务，本地 Ollama / LM Studio / vLLM 或云端皆可
- 平台：Windows 优先（API Key 用当前用户级 DPAPI 加密落盘）

---

## 快速开始

需要 Node.js 20+、Docker Desktop 和 Docker Compose。

```powershell
npm run directus:up
npm run directus:provision
npm start
```

- 工作台：`http://127.0.0.1:4173`
- Directus 后台：`http://127.0.0.1:8055/admin/content/terms_ja_jp`

管理员凭据在本机 `directus/.env`（已 gitignore）。服务端用单独的最小权限 Service Token，不向浏览器暴露管理员令牌。

`directus:provision` 是幂等的，随时可重跑以补齐缺失的集合、字段、权限与种子数据。它只补建缺失项，**不会重写已存在字段的界面元数据**——比如改变目标语言列表后，旧的下拉选项需要另行处理。Schema 快照在 `directus/schema/snapshot.yaml`，用 `npm run directus:snapshot` 更新。

**Directus 是唯一的生产存储，连不上就直接启动失败。** 这里曾经会静默回退到本地 JSON，代价比看起来大得多：回退后全部风格证据、翻译记忆和风格规范都不可见，模型在零参考的情况下继续翻译，同时新写入落到 `data/` 形成数据分叉，界面横幅并不足以让人及时发现。宁可起不来，也不要带着残缺资产跑。JSON 存储仍保留，但只服务于单元测试。

### 模型配置

界面右上角「模型设置」。Base URL、模型名与 API Key 保存在本机 `data/runtime/`（已 gitignore），Key 用 Windows 当前用户级 DPAPI 加密——换用户、重装系统或复制到别的机器都需要重新输入。

可分别指定四个模型角色，留空则统一回落主模型：

| 角色 | 用途 |
| --- | --- |
| 主模型 | 常规翻译与 AIQA |
| 快速模型 | 机器初译（`mt_post_edit` 路线的底稿） |
| 高质量模型 | 高风险内容、质量升级重试、后编辑 |
| Embedding | 语义向量检索，可指向独立服务 |

主模型 API 不支持 `/embeddings` 时（如 DeepSeek 官方 API），把 Embedding 单独指向本地 Ollama 的 `nomic-embed-text` 即可；完全未配置时自动回退词面检索。

填写输入/输出价格（美元 / 百万 token）后，技能评测会启用真实成本门禁；留空则跳过成本判定，不会因为没计量而锁死晋升。

环境变量优先于界面配置：

```powershell
$env:LLM_BASE_URL='https://your-provider.example/v1'
$env:LLM_API_KEY='your-key'
$env:LLM_MODEL='your-model'
npm start
```

## 数据隔离

正式术语与翻译记忆各存四张物理表：

```text
terms_ja_jp                 translation_memory_ja_jp
terms_ko_kr                 translation_memory_ko_kr
terms_zh_hant_tw            translation_memory_zh_hant_tw
terms_th_th                 translation_memory_th_th
```

每次请求必须提交受支持的 `locale`，后端用固定白名单映射到唯一表名。不接受客户端指定任意集合，不存在跨语言 fallback。`data/assets/*.json` 只是初始迁移源，不是写入目标。

共享集合按 `target_locale` 隔离：`corpus_documents`（原始语料）、`term_import_batches` / `term_candidates`（导入批次与候选）、`style_profiles` / `style_evidence`（风格规范与证据）、`qa_runs` / `qa_cases`（质检轨迹与错题）、`learning_trajectories` / `translation_skills` / `skill_evaluations`（学习闭环）、`quality_assets` / `quality_runs`（固定评测资产与门禁记录）、`training_runs`（微调任务）。

## 一句话的完整路径

### 内容分流

同时判三件事：**语体**（14 类，决定写作口径与语域容忍度）、**业务领域**、**事实锚点**。

语体优先读需求表自己声明的用途——`位置` / `描述` 等列命中关键词时直接采用（视频标题→宣发、导航栏文本→UI、FAQ→通用），比从正文猜测可靠；人工指定仍然最优先。领域在语体已决定时直接继承（宣发→市场营销、社媒→社区运营），否则按关键词推断。判定结果实时显示在下拉旁，不必等翻译跑完。

事实锚点由受控词表抽取：平台、地区、日期、折扣、条件、URL、占位符、字符上限。只认词表里的东西，绝不猜。

**领域是收窄维度，永不让检索归零。** 本项目 99% 资产归在 game 下，按 `domain` 严格过滤会让参考译例直接清零。实现上先不限领域取回、再在内存收窄，收窄后为空则退回全量并在界面标注「该领域无资产，检索已放宽到全部」。

### 资产检索

术语匹配先过治理准入：**过期、未生效、已废弃的术语不参与匹配**，标了其它平台或地区的术语也不参与。区分大小写的术语在大小写不符时降级为「待确认」而非当作命中；标了保留原文的术语，期望译文里出现的是原文形态本身而不是 target 字段。

翻译记忆按相关度过门槛，再按投放亲和度（平台、活动、地区、渠道、新鲜度，90 天半衰）排序。**亲和度只参与排序，不参与门槛**——把可信度和相关度相加曾让完全无关的译例挤进上下文，这里不能重演。

### 风险分级与路线

按事实密度、受保护标记数、承诺强度和文本长度算出四档风险，再选路线：

| 路线 | 用于 |
| --- | --- |
| `direct` | 低风险短文本 |
| `reflective` | 常规文本，初译后自检并最小修订 |
| `fact_guarded` | 事实密集内容，高质量模型 + 强化事实约束 |
| `transcreation` | 宣发社媒，多候选后择优 |
| `mt_post_edit` | 快速模型出底稿，高质量模型按资产约束后编辑 |
| `multi_candidate` | 生成多个候选供人工选择 |

### 两层质量检查

**确定性层**不调模型，同输入必定同输出：强制术语、保留原文、禁用译法、占位符、数字、目标语言标点、事实锚点、语域。

- 数字按**数值等价**校验而非字面包含。中文日期简写（820 = 8 月 20 日）展开成目标语言写法不算漏译，只有确实无法还原时才提示。带单位的数值（50%、100 元）仍要求原样保留。
- 标点按语种配置在 `src/orthography.mjs`，同一符号重复只报一条。当前作品名约定：日语 `『』`、韩语 `《》`、繁中 `《》`。韩语正字法对多种括号都允许，此处取本项目既有人工资产的统一写法。
- **语域走确定性分类器而不是模型自由判断**：太营销 / 太网感 / 太普通三个维度，用分语种词表加结构特征打分，每条判定都带证据词、分数、阈值和分类器版本，因而可以回归。判定相对语体——同一段促销文案在宣发语体里合格，放进公告就超标；但宣发也有上限，不是无限放行。写作口径与语域容忍度共用同一张表，生成和评审不会各自漂移。

**AIQA 层**按 MQM 六个一级维度出可定位的问题。fidelity 按**信息点**判定：先从原文列出可核实的信息点（事实、数字、日期、名称、平台、条件、否定、承诺强度），再逐个检查能否从译文还原；中文话语标记、程度副词、范畴词、代词显化、句子拆合与语气词改写一律不算漏译增译。低于门槛自动最小修订并重新盲审，最多两轮。

**审校证据分权威等级**：只有人工批准的译例会作为「已批准译例」提交给审校模型；系统自己 QA 通过的机器译文单独列为 `machineDrafts`，仅用于发现同一文档内自相矛盾，提示词明确禁止拿它当正误依据。否则一次错误会在下一次审校里升格为规范。

### 质量路由与人工审阅

拿 AIQA 分数、硬错误数和风险等级决定去向：自动放行、升级模型重试、转人工。风险越高门槛越严（低风险 88 分，关键风险 96 分且仍需人工确认）。AIQA 未完成一律转人工。

人工处置有四种：接受、**部分接受**、拒绝、要求修订。每次处置生成结构化回执并写进学习轨迹。

## 资产沉淀：谁能写正式资产

**AIQA 通过的机器译文永远不会写进正式翻译记忆。** 它只留在 QA 运行记录、学习轨迹和待审批的 QA 案例里。正式记忆只有一个来源：人工采纳。

人工采纳一次，同时发生四件事：

1. 写入正式翻译记忆，同原文的旧版本自动降级
2. 生成风格证据，并带上被替换掉的机器初稿——**人改了什么**才是风格信号，只看定稿无法区分改的是语气、长度还是称谓
3. 批准关联的 QA 案例
4. 从终稿提取术语候选**送审**（候选不是正式术语，要单独审批）

机器初稿只从服务端记录的轨迹取，不接受客户端提交，否则蒸馏学到的是可以被伪造的"改动"。

## 学习与晋升

学习范围由 `目标语言 × 内容语体 × 业务领域 × 项目` 四维严格隔离，语种之间不共享技能版本。

### 翻译技能（Champion / Challenger）

生产只读 `champion`，模型复盘轨迹产出的改进先成为 `challenger`。候选只能调整上下文范围、检索数量、风格指令与 QA 门槛等**策略**，不把某个偶然译法硬编码成通用规则。

候选用过的所有轨迹都从留出集排除；至少积累 20 条独立的人工批准终稿才会真正重跑新旧版本。强制术语正确率或硬错误退化时一票否决。评测以后台任务运行，每完成一对就落盘检查点（`data/learning/jobs/`），服务重启后可续跑而不是从头重烧模型调用。评测前会剔除与留出原文同源的记忆、QA 案例与风格证据，防止标准答案泄漏。

模型返回的策略补丁按不可信输入处理：白名单校验、未知字段丢弃、数值区间夹紧、长度截断、控制字符剥离，并拦截「忽略以上规则」类注入特征，净化明细记录在候选的 `metadata.sanitization`。

### 风格规范

**规则级累积。** 风格规范是带稳定 id 的规则集，不是每轮重写的散文。蒸馏产出的是增量操作（keep / update / add / retire），本轮没提到的规则**不会消失**——只有连续多轮（默认 4 轮）没被证据确认才退休，且写明原因、保留可复核。

这是"素材越多风格越准"成立的前提。旧实现每轮只看最近 N 条重写整份规范，第 10 条证据学到的规则会随窗口滚出去而静默消失：同一作用域 481 条证据实测能产出 181 到 1466 字不等的规范，差别只来自抽到哪 30 条。

蒸馏闸门：同作用域还有待审草稿时不再生成新草稿；上一版之后证据池必须再新增满一个增长窗口（默认 8 条）。因此任何时刻一个作用域最多只有一个待审草稿，界面显示本次跳过的具体原因。

**风格草稿走独立的配对评测线。** 技能评的是检索条数、附加指令与 QA 门槛；风格评的是风格文本本身。评测时唯一变量就是风格规范，两侧的技能、留出集、检索隔离完全一致。

两条不可省的规矩：AIQA 会读风格规范当 nuance 尺子，所以两侧一律用**当前生效版本**打分，否则草稿等于自己给自己判卷；相应地 QA 分只保留"不得下降"的护栏作用，能作为晋升理由的只有与人工终稿的编辑距离、强制术语正确率和硬错误数——这三项不受风格规范影响。结论反对时激活返回 409，强行启用会记为 `forced`，未评测直接启用记为 `unevaluated`。

反例同样入池：同事只提出问题、没给改写时，被否决的正是当前译文，它按 negative 入库并保留否决理由，绝不会当正例喂给模型。

### 规则冲突审查

风格规则、技能附加规则和译者画像都往同一份提示词里写文字，彼此并不知情：技能可能带着"句尾用简体"晋升，而风格规范写着"句尾统一敬体"，模型只会挑一条照做。

审查把三方规则拉平成同一形状后逐对比较，先用确定性预筛剔掉只谈不同方面的组合，再把至多 12 对交模型裁决。判为矛盾的门槛很窄：必须能指出一个**同时遵守两条就不可能**的具体场景；总则与例外、适用场景不同、要求不同但可共存的一律不算。模型不可用时只报"模型不可用"，绝不把预筛候选当结论。

裁决为真后按证据强弱衡量：风格规则按累计证据数加轮次计权，技能规则折算成中等权重，势均力敌交人工。**只有输的那条是风格规则时**才给出退休按钮；输的是技能规则或画像时一律只报告不动手——技能须经评测晋升，画像须走草稿流程，扫描不能代劳。

## 固定评测资产与发版门禁

留出集取自动态人工终稿，会跟着资产一起漂移，因而无法证明"越用越好而不退化"。固定质量资产解决的是这件事。

- **Gold Set**：原文 + 参考译文 + 强制术语 + 事实锚点 + 禁用译法 + 占位符。内容不可变，改内容只能发新版本；同族启用新版本时旧版本自动退役。
- **失败回归集**：人工拒绝过的译文 + 人工修订后的译文。入集要过两道人工闸门——先批准案例，再单独审批入集，拒绝必须写原因。

候选晋升前在这套固定资产上真跑一遍：每个样本走生产同款链路，带隔离，**样本自己的终稿不会通过翻译记忆回流成它自己的答案**。跑完由确定性规则打分：回归案例复现被拒译文即一票否决，Gold 术语准确率低于 0.98 或事实准确率低于 1.0 即阻断。没有一条通过的门禁记录，晋升接口直接拒绝。人工可署名强制放行，但记录里的结论保持真实，不会被美化成通过。

跑门禁要花钱（每个样本一次翻译加一次 AIQA），所以它是晋升前跑一次，不是每句都跑。

## 微调与蒸馏流水线

**SFT / DPO 导出。** SFT 取人工采纳的终稿，assistant 轮永远是人的措辞；DPO 取两种偏好信号——人工改写了机器初译，以及人工批准的 QA 修订。每条丢弃都记原因（未完成、未采纳、跨作用域、重复、无偏好信号、长度越界）。

**命中固定评测资产的原文一律硬丢弃。** 少了这一步，模型会在自己的考卷上训练然后考满分。

**训练任务。** 建任务时重新导出并对序列化内容取 sha256，拿到 `.jsonl` 的人可以自己复算核对。状态机不允许跳步（draft → frozen → submitted → running → succeeded → registered → promoted）。交接清单只带指纹不带正文。

**产出模型要投产，必须自己拿一条通过的门禁记录**，和任何候选技能一视同仁。训练本身在外部执行，这是整条链路上唯一不在本仓库内的环节。

## 工作流

### 术语导入

拖入 `.xlsx` 或 `.csv` 即自动开始结构识别，不需要补表头。可直接复制 `samples/term-import-template.csv` 作模板，不需要的目标语言列删掉即可。

1. AI 结合整列与成对行关系识别中文列、目标语言列与表头结构，后端校验真实列号
2. 去除网址、纯数字、空值、重复对照与元数据；完整句子不当术语，转入翻译记忆和风格证据
3. 检查已存在项及同源词译法冲突
4. 可选的模型二次判断，不可用时回退本地规则
5. 只把人工勾选的候选写入对应语言物理表

导入可断点续传。判为"需复核"的默认不勾选，"已存在"和"已排除"不能直接导入。候选中文与译法可在审核表格里直接改。

### 批次与文件翻译

支持粘贴长文与 `.txt`、`.md`、`.docx`、`.xlsx`、`.csv`。分段不使用固定字数：默认一个完整句子作为翻译单元，可切换为自然段、Word 段落或 Excel 单元格。

Excel 拖入后由模型识别正文、补充信息、约束、已有译文与忽略列，结论经后端列号与角色白名单校验；模型不可用时回退本地结构规则并标注"规则降级识别"。**只有正文列生成翻译单元**，同行的补充信息、约束和已有译文作为 Context Pack 输入，不会被误当正文翻译。

系统先展示完整分段队列，不直接开始。启动后先对整份文档确定统一语体与基础风格，再为每段携带上下文、文档位置、行内约束、已有参考译文、术语匹配与风格配置。上下文只用于消歧与保持连贯，提示词明确禁止把它混入译文。

批次可暂停续跑、跳过分段、编辑译文、重试失败项。导出保留原文件格式：未完成部分保留原文，DOCX 写回原段落，XLSX 只写回识别出的正文单元格，TXT / Markdown / CSV 保留原结构。

### Auto QA

粘贴原文与译文即可逐句质检。先按句切分并自动对齐（语义向量优先，不可用时由模型逐句对齐，支持拆句并句，可标出整句漏译增译），再对每句分层独立审查：基本检查（本地规则 + 语言正确性专项）、语义忠实性（critical 封顶 65 分）、nuance 一致性（对照风格规范、已批准译例与历史证据）。综合分按 20 / 50 / 30 加权，模型不可用时只跑本地基本检查层。

**分数按段平均而非全文累加**：每段独立计分后取平均，坏掉一段只影响 1/段数；阻断问题在段级压到 60/65，文档级封顶 65，另有 `blockedSegments` 计数区分"坏一段"与"全坏"。

每次质检自动存为任务中心的 Auto QA 报告，可回放不重烧模型。

### 分享验证与反馈回执

翻译批次与 Auto QA 报告都能一键生成分享链接（局域网免登录，token 即权限），创建即时返回。语素拆解与字面直译由后台任务生成，进度可见、服务重启后续跑、链接长期有效。

同事在独立分享页看到每段的原文、译文、QA 评分与问题，可逐段提要求并附建议译法。**每条意见的处置结果逐条回到分享页**：采纳还是未采纳、处理说明、是否改了译文、处理人与时间——提意见的人看得到自己的意见去了哪，而不是只看到一个总数。

右上角反馈铃铛每 15 秒轮询新反馈，可集中批准入风格证据池或忽略。

### 后台任务中心

术语导入、Embedding 重建、批次导出、分享生成、技能评测统一进入任务中心，进行中显示进度、失败显示原因、可删除。Embedding 重建在探针发现外部向量服务不可用时自动改用本地词面向量。

## 参数设置

页头「参数设置」把原本写死在代码里的调优参数集中到界面，改动即时生效无需重启：QA 通过分与修订轮数、Auto QA 三维权重与各级扣分、参考译例与 QA 反例条数、上下文段数、风格蒸馏阈值与增长窗口、评测最小样本、分享语素上限、按语种的作品名括号约定。

每项都有区间校验：越界夹紧、三维权重之和必须为 100（否则整组回落）、增长窗口不得大于阈值（否则功能被配死）。被自动校正的项会逐条列出而不是悄悄改掉输入。

已有环境变量（`KAMI_STYLE_DISTILL_*` / `KAMI_AUTO_PROPOSE_*`）仍然优先，面板会标注并置灰。技能策略与面板的优先级：技能里的值仍等于出厂值说明学习循环没动过它，听面板；已偏离出厂值说明是评测晋升的结果，尊重技能。

## 当前边界

- 旧版 `.xls` 需先另存为 `.xlsx`；JSON、YAML、PO、XLIFF 与游戏资源包尚未接入结构化回写。
- DOCX 保留文档容器、段落与非文本对象，但一个段落内跨多个样式 Run 的文字写回时会合并到首个 Run；复杂排版建议导出后人工检查。
- 模型不可用时靠本地整列规则推断；纯汉字日文、极短样本及高度相似的简繁列仅靠规则存在歧义，可在导入策略中指定目标语言后重试。
- AI 只做候选保留 / 排除判断，不会擅自改写原表中的中外术语。
- 智能术语匹配结合编辑距离、字符重排、别名与模型译文对齐；完全没有词面关联的同义概念仍需补别名。
- 模型微调本身在外部执行，本仓库只负责数据冻结、配方记录、产物登记与投产门禁。
- 译文质量取决于接入的模型和为各语言积累的正式资产。
